# APS-027 実施記録(「ブー」音の根本修正: DC平衡LFSRタップ再選定+タイトル版表示)

- 課題ID: APS-027
- 版番号: v001
- 実施日: 2026-08-08
- 実施者: Fableサブエージェント(worktree `atari-lynx-shooter-aps027-wt`、基点 f655b78 = APS-026)

## 背景(2回連続で聴感評価が改善しなかった)

1. APS-024: Stage1 BGMを「きらきら星」へ差し替え → ユーザー「BEEP音のまま」
2. APS-026: 全チャンネルへintegrateビット(control bit5)を一律追加+音量エンベロープ → ユーザー「和らいでいない。ブー、という音」

APS-026はレジスタレベルでは意図通り(control=0x3B、volume 0x11→0x05の減衰)動作していたため、
「レジスタが正しいのに音が悪化した」= **integrateモードそのものの理解が間違っている**可能性を
最優先で疑い、Gearlynxのソースから原理を追った。

## 調査過程

### 1. Gearlynx `mikey_inline.h` の `AdvanceLFSR()` を精読

```
data_in = XNOR(parity(lfsr & taps_mask))          // タップのXNOR
lfsr    = ((lfsr << 1) & 0x0FFE) | data_in        // 12bit LFSR
非integrate: output = data_in ? +vol : -vol        // 瞬時切替(矩形波)
integrate:   output = clamp(output + (data_in ? +vol : -vol), -128, +127)
```

決定的な発見: **integrateモードは「波形を滑らかにするフィルタ」ではなく「±volの累積器」**。
累積が発散しない必要十分条件は、LFSR出力列の1周期内の1と0の個数が等しいこと(DC平衡)。
APS-026の前提(「integrateを立てれば音が和らぐ」)はこの条件を欠いていた。

taps_maskの構成: feedback bits0-5 → tap0-5、feedback bits6-7 → tap10-11、control bit7 → tap7。
本ゲームはLFSR上位ビット(bits8-11、`other`レジスタ上位ニブル)を一切初期化しないため、
tap10/11/7を使う設定は初期状態が不定になる。今回の再選定ではtap0-5のみに限定した。

### 2. 現行4波形のシミュレーション(`scripts/sim-mikey-lfsr.py`、Gearlynx互換実装)

| 波形 | fb/sh | 周期 | 1-0の差/周期 | integrate時クランプ張り付き率 |
|---|---|---|---|---|
| TONE | 0x3f/0xac | 7 | -1 | 42.7% |
| METALLIC | 0x36/0x5a | 63 | -1 | 17.4% |
| NOISE | 0x1f/0x7f | 6 | +4 | 83.2% |
| PULSE | 0x24/0xb4 | 9 | +1 | 33.2% |

**全波形が不平衡**。差が1でもunderflowごとに±volずつ一方向へドリフトするため、
vol=0x11なら TONE は約 128/17*7 ≈ 50tick(underflow約500Hzで0.1秒)でレール(-128/+127)に到達し、
以後は「レール上の小リップル+LFSR周期ごとの段差」に退化する。これが低く歪んだ「ブー」の正体。
エンベロープ(0x11→0x05)はレール付近のリップル幅を変えるだけで、聴感上ほぼ消失していた。

### 3. 実測による裏付け(Gearlynx MCP、`get_mikey_audio`でoutputレジスタを直接読む)

`scripts/verify-audio-output-acc.py`(新規)でoutput=integrate累積器を30msごとにサンプリング:

- 旧構成: シミュレーションの張り付き挙動と整合(下記「対策後の実測」と対比)。
- main側 `dist/asteroid-patrol.lnx`(SHA `10373b88...`)は control=0x1B・output=±17 の2値のみで、
  **APS-026より前の古いビルド(integrate無しの生矩形波)だった**ことも判明。
  distの成果物はコミット時点と一致しない場合がある点に注意(検証は必ずビルドし直すこと)。

### 4. DC平衡パターンの探索(`scripts/search-balanced-lfsr.py`)

feedback 0x01-0x3F × shift_low 0x00-0xFF を全探索し、定常周期がDC平衡になる組を列挙した。
知見:

- **単一タップk+下位k+1ビット均一シード** → `x[n] = NOT(x[n-(k+1)])` のtwisted ring counter
  に退化し、「1がk+1個→0がk+1個」の完全平衡列を恒久的に出す。integrateと組み合わせると
  振幅`(k+1)*vol`のクリーンな**三角波**(柔らかい音色の定石。NES三角波チャンネル相当)。
  ウォームアップ(シード状態が周期軌道に乗るまでの過渡)も出力ビット列としては最初から周期列で、
  過渡由来のDCオフセットが残らない。
- 複数タップの平衡解(例 fb=0x2a, fb=0x19, fb=0x1f系)も多数あるが、周期軌道に乗るまでの
  ウォームアップ出力が不平衡で、**恒久的なDCオフセット**(最大で数tick×vol)が累積器に残る。
  vol=18でオフセット~126に達し得てクランプ余地を食うため、採用を見送った(試して捨てた案)。
- 単一タップでもシードの下位ビットが均一でないと崩れる(例: fb=0x08, sh=0x0a(1010) →
  ほぼ交互列の周期8で三角にならない)。シード指定は必須。

### 5. 採用値の決定

- **TONE: fb=0x04(tap2), sh=0x07** → 111000周期6、三角波。旧周期7 → 一律+2.7半音の移調。
  シミュレーション: 平衡+0、クランプ0%、振幅3*vol(最大vol27で81 < 127)。
- **PULSE: fb=0x08(tap3), sh=0x0f** → 11110000周期8、三角波。旧周期9 → 一律+2半音。
  周期の近さ(9→8)を優先して選定。振幅4*vol(最大vol30で120 < 127)。
- **METALLIC/NOISE: APS-013値のまま、integrate非適用**。不平衡な擬似ランダム列をintegrateすると
  ドローンが再現する(NOISEは酔歩化して低いゴロゴロ音=まさに「ブー」)。硬い音色はSFXの
  アクセントとして意図的なので、非integrateの矩形系に戻すのが正しい。
- 検討して見送った案: (a) integrate全廃+波形テーブルのみ再チューニング → 矩形波のままなので
  「BEEP」評価が変わる根拠がない。(b) METALLIC用の平衡長周期(~63tick)パターン →
  周期内の部分和の振れが大きくクランプ管理が難しい上、SFXの音色が意図せず変わる。
  (c) PULSEを周期4(fb=0x02)へ → 移調が1オクターブ超になりStage2の音域が跳ね上がるため却下。

## 変更内容

### `src/main.c`

1. `SOUND_REG_OUTPUT 2u` を新設。
2. `SoundWaveRegister` へ `integrate` フィールド(0 or `SOUND_INTEGRATE_MODE`)を追加し、
   control A書込みを `pitch->prescaler | SOUND_TIMER_ENABLE | wave->integrate` に変更
   (APS-026の全チャンネル一律ORを廃止)。
3. `sound_wave_registers` を上記採用値へ更新(TONE/PULSEのみ変更、integrate付き)。
4. フル再設定時とサイレンス時に `channel[SOUND_REG_OUTPUT] = 0u` を書き、累積器を確定リセット。
   前の音符/SFXの残留レベルからの開始によるクランプ押し出しと、チャンネル無効時に残留値が
   DCとしてミックスされ続ける問題(Gearlynxは無効チャンネルのoutputをPCMとして混合する)を防ぐ。
5. タイトル画面へ `tgi_outtextxy(52u, 90u, "V" GAME_VERSION_STRING)` を追加(`include/version.h`を新規include)。

## アーキテクチャ評価(率直に)

- 現行アーキテクチャ(75Hzシーケンサ+SoundStep+固定波形テーブル)は、**「柔らかい・曲らしい」方向に
  今回の三角波化までは到達できる**。integrate+DC平衡タップはMIKEYで柔音色を出す正攻法であり、
  エンベロープも初めて機能する。ただし到達点は「良質なチップチューン」であり、
  楽器らしい音(倍音の時間変化、残響)には原理的に届かない。
- それ以上を求める場合の選択肢は (a) 2チャンネルデチューン/ビブラート(現アーキテクチャ内で可能、
  channel D追加はAPS-023リファクタで1行差分)、(b) DAC直接サンプル再生(8kHz monoで8KB/s。
  ROM容量とCPU予算からループBGMには非現実的、短いジングル限定なら可能性あり)。
  まず今回の三角波の聴感評価を待ってから判断すべき。

## 残課題

- **最終的な聴感評価はユーザーの領分**。機械検証は「張り付きが消え、振幅がエンベロープに追従する
  三角波が出ている」ことまで。
- TONE/PULSEの一律移調(+2.7/+2半音)により、Stage3のw0ベース(移調)とw1メロディ(非移調)の相対
  チューニングが約2.7半音ずれる。w1は非調和的なmetallic音色のため実害は小さい見込みだが要聴感確認。
- `dist/`の成果物がコミットと一致しない場合がある(main側で実証)。検証は必ず再ビルドから行うこと。
