## 目的

`MOVABLE_SET_HPOS/VPOS`のcc65生成store不具合を最小修正し、敵弾SCBへGameStateの座標を正しく書き込む。v010でGearlynx 1.2.21 GUI/headless双方について、GameState slot0=`x=100,y=40,active=1`に対し、Suzy投入前SCB slot0=`SPRCTL0=0x28,SPRCTL1=0x08,hpos=0,vpos=0`、slot3=`SPRCTL1=0x0C,hpos=0,vpos=0`を直接確認済み。原因は`src/main.c:522-535`のfield-address macroがSCB base offset 0へstoreすること。

## 実装方針

- `src/main.c`の`MOVABLE_SET_HPOS/VPOS`だけを、cc65が確実にSCB byte offset `7/9`へ書く表現へ修正。`SCB_RENONE` layoutは`.cache/cc65-2.19/source/include/_suzy.h:176-184`準拠（sprctl0=0、sprctl1=1、next=3、data=5、hpos=7、vpos=9、size=11）。
- 既存のSCB chain、draw order、collision、sprite data、OPT診断操作は変更しない。必要ならhost診断でslot0/slot3の座標・SPRCTL0・SPRCTL1をFAIL条件として固定。
- release `APS056_DIAGNOSTIC`未定義経路にも同じmacro修正が入るため、release ROMのSCB座標・MAIN余剰・既存hash変化を明示検証。

## 必須確認

- `GameState active/x/y`、trace、実`tgi_ioctl` chainのslot0/slot3が期待値一致: slot0=`SPRCTL0=0x05,SPRCTL1=0x08,hpos=100,vpos=40`、slot3=`SPRCTL0=0x05,SPRCTL1=0x0C,hpos=80,vpos=9`。
- GUI/headless Gearlynx MCPでpost-submit framebuffer/screenshotのslot0 `(100,40)` pixel probeがenemy-bullet palette colorを含むこと。
- `make aps056-diagnostic-host`、`make test smoke-host lint`、`make clean && ./scripts/verify.sh`、診断LNX検査、`python3 -m py_compile scripts/verify-aps056-diagnostic-gearlynx.py`、`git diff --check` PASS。
- release/diagnostic ROM size、SHA-256、LNX、map MAIN余剰、production差分、開始/終了HEADを記録。ISSUES.mdへv011結果を追記。
