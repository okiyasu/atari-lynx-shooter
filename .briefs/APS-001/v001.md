## 依頼

Handy v0.9.11 と Gearlynx 1.2.21 の両方で、ROM起動後の画面が激しくチラつき、内容を判別しづらい。描画ループをコード根拠で調査し、安定して視認できる描画へ修正する。ロジックテストが通っているという理由だけで描画側を断定せず、実装と cc65 2.19 の Lynx TGI ドライバ／同梱資料を照合すること。

未検証の仮説は、割り込み駆動ダブルバッファの切替完了を待たず、次フレームの `tgi_clear()` と再描画を開始している競合である。現行 `src/main.c` は `draw_game()` 末尾で `tgi_updatedisplay()` を呼ぶ一方、通常ループでは次の描画前に `tgi_busy()` を確認していない。ローカルの `.cache/cc65-2.19/source/libsrc/lynx/tgi/lynx-160-102-16.s` と `.cache/cc65-2.19/source/doc/lynx.sgml` を一次資料として実際の swap request／VBlank IRQ／draw page 切替を確認すること。この仮説が外れていれば、別原因と根拠を報告すること。

## 実装・検証要件

1. 原因を `src/main.c` と cc65 TGI ドライバの該当行・挙動に結び付けて説明する。
2. VBlank待ち／バッファ切替の同期位置を明示し、表示中バッファへクリアや途中描画が及ばない理由を説明する。無制限ループ速度でゲームロジックだけが進み続けないことも確認する。
3. 変更は最小限とし、75Hz、割り込み有効化、既存のゲーム仕様を維持する。
4. `./scripts/verify.sh` を実行し、クリーンROMビルド、warnings-as-errors相当のlint、既存14件以上のロジックテスト、シェル構文検査、LNXヘッダ検査をすべて通す。要約だけでなく、実コマンドと主要な実出力を最終報告に載せる。
5. `git diff --check` と `git status --short` を実行し、意図したファイルだけが変更されていることを確認する。
6. エミュレータ目視確認が可能なら Handy と Gearlynx の双方で実施する。BIOS設定やGUI操作を要して実施できない場合は「未確認」とし、ユーザーが確認すべき具体項目を列挙する。目視未実施を自動検証成功で代替したと表現しない。
7. `ISSUES.md` の古い「エミュレータ未導入」記述は、今回確認済みの環境（Handy v0.9.11、Gearlynx 1.2.21、HandyはBIOS設定済み）と矛盾しないよう更新する。
