## 検収差し戻しの事実

Dev Front が現行 `0.39.0` ROM で実行した以下の統合検証は、title / GAME OVER voice は成功した一方、BGM channel A で失敗した。

```text
python3 scripts/verify-title-voice-gearlynx.py --mode title
# OK: title voice varied channel D, stopped, and transitioned to Stage 1
python3 scripts/verify-title-voice-gearlynx.py --mode game-over
# OK: GAME OVER voice varied channel D, stopped, and unlocked input gate
python3 scripts/verify-audio-gearlynx.py --channel 0 --seconds 8
# FAIL: fewer than 2 distinct pitches observed -- channel is silent or stuck on one note
# channel 0: 0 note change(s) in 8.0s
```

原因候補は `scripts/verify-audio-gearlynx.py` の入力同期不備である。同scriptはtitleを描画後、`controller_macro` の `tap a` → `wait 30` → `tap a` と固定sleepだけで開始を仮定している。現行gameは title armed 状態で**持続した**FIRE入力を受理して `title_voice_pending` を立て、約2.193秒のblocking title voice完了後に `game_title_voice_complete()` で Stage 1へ進む。`verify-title-voice-gearlynx.py` は実際に `title_start_armed=1` をmemory pollしてから `press a` を使い、同じROMで成功している。`tap`が入力ポーリングの間に消えるとtitleのままになり、BGMは開始されない。実ROMのBGM回帰と断定してはならない。

## 要求

`scripts/verify-audio-gearlynx.py` のみを主対象に、BGM A/C および既存のB SFX検証への遷移を状態同期型に修正する。

- `main_bss_game_address()` と現行 `GameState`レイアウトを用い、起動後にTITLE（stage=1、phase=TITLE）と `title_start_armed=1` を期限付きpollで確認してから、`controller_macro` の持続 `press a` を一度だけ送る。瞬間 `tap` と固定`wait 30`への依存を除く。
- title voice完了後の Stage 1導入と、BGMを観測できる段階までをdeadline付きmemory pollで待つ。必要なら `phase != TITLE`、`SoundState`の論理BGM出力またはMIKEY channel A/C activeを組み合わせる。固定wall-clock sleepだけで成功を判断しない。
- channel 0/A と channel 2/C は、現行の複数pitch変化と75% logical→MIKEY gain照合を保ち、実ROMで安定してPASSさせる。channel 1/Bの既存SFX state injectionも、同じ状態同期済みStage 1 NORMALから開始する。
- timeout時は実際に観測した stage / phase / armed / pending / voice状態（読める範囲）を短く出し、title未受理・voice待ち・BGM未開始を識別可能にする。秘密値、BIOS、外部資産を出力しない。
- ゲームruntime、sound table、MML、音声asset/metadata/hash、Timer 3/voice stream、cart layout、stage JSON/generator、sprite/palette、ゲーム速度、`include/version.h`を変更しない。これは検証器の同期是正であり、`GAME_VERSION_STRING` は `0.39.0` のままとする。
- `ISSUES.md` にはAPS-039として、失敗条件・原因・修正内容・実測再検証結果・実機未確認を追記する。README/designは検証手順の記述が実態と矛盾する場合だけ最小更新する。既存briefを上書きしない。
