## 背景

Phase 3R2(movable SCB静的チェーン化)はv046で完了し、gate(a)/(b)/(d)を達成してコミット・push済み(`b1890b2`)。ただし、gate(a)全体(2VBlank以下)の最終合否には、movable SCB(F、0.779VBlank)以外に残る約9VBlankの内訳分解が必要と申し送っていた。

これに着手し、公開シンボルへの逐次breakpoint(v019の1点ずつset→hit→remove手法)でフレーム全体を分解した結果、**残り9VBlankの正体はほぼ全てstatic_layer_draw内のSCB構築処理**であり、さらにその内部を分解したところ、**HUDテキストのビットマップ再構築(`append_hud`/`build_text_line`)が突出して重い**ことが判明した(ISSUES.mdに詳細記録済み、`evidence/APS-053/phase-3r-frame-breakdown-v047.json`/`v048.json`)。

static void append_hud(const GameState* game)
{
    char text[21];
    unsigned char i;
    unsigned long score_value;
    unsigned int timer_value;

    score_value = game->score;
    for (i = 5u; i != 0u; --i) {
        text[8u + i] = (char)('0' + score_value % 10ul);

```c
/* STATIC_LAYER_FONT_HEIGHT=7, STATIC_LAYER_FONT_WIDTH=5, text length=20固定 */
static void build_text_line(unsigned char* output, const char* text)
{
    unsigned char row, c, column, bits, byte, pixel, index, length, pixel_bytes;

    length = 0u;
    while (length < 20u && text[length] != '\0') ++length;
    pixel_bytes = (unsigned char)
        (((unsigned int)length * (STATIC_LAYER_FONT_WIDTH + 1u) + 7u) / 8u);

    byte = 0u;
    for (row = 0u; row < STATIC_LAYER_FONT_HEIGHT; ++row) {      /* ×7 */
        output[byte++] = (unsigned char)(pixel_bytes + 1u);
        for (pixel = 0u; pixel < pixel_bytes; ++pixel) {
            output[byte + pixel] = 0u;
        }
        pixel = 0u;
        for (c = 0u; c < length; ++c) {                          /* ×20 */
            index = text_font_index(text[c]);
            bits = index < STATIC_LAYER_FONT_COUNT ?
                static_layer_font_bits[index * STATIC_LAYER_FONT_HEIGHT + row] : 0u;
            for (column = 0u; column < STATIC_LAYER_FONT_WIDTH; ++column) { /* ×5 */
                if ((bits & (unsigned char)(16u >> column)) != 0u) {
                    output[byte + pixel / 8u] |= (unsigned char)(0x80u >> (pixel & 7u));
                }
                ++pixel;
            }
            ++pixel;
        }
        byte = (unsigned char)(byte + pixel_bytes);
    }
    output[byte] = 0u;
}
```

## 気になる点(検証はしていない、参考まで)

- `score_value`が`unsigned long`(32bit)で、5桁分`% 10ul`/`/= 10ul`(**32bit除算・剰余**)を計5回実行している。6502に除算命令はなくソフトウェアルーチン(cc65ランタイムヘルパー)呼び出しになり、32bit除算は16bit除算よりかなり重いはず。timer_valueは`unsigned int`(16bit)なので同じ構造でもコストは軽いと推測される。
- `build_text_line`本体はHEIGHT(7)×length(20)×WIDTH(5)=700回のビット演算ループ+`text_font_index`呼び出し140回(文字ごとに1回、行ごとに再計算しており本来は列方向のみで足りるはずだが実装は行×文字の二重ループ内で毎回呼んでいる)。
- `append_hud`は`static_layer_draw`から**フェーズを問わず毎フレーム**呼ばれる(スコア/タイマー等の変化を追従させるため)。fixtureの生死状態に関わらずE1cのコストがfull/emptyでほぼ同じ(7.276VB/7.354VB)なのはこの毎フレーム再構築という設計と整合する。
