## 背景

v025でcompact glyphのmaskを `4 >> column` から `8 >> column` に修正し、`src/static_layer_data.c` を再生成した。`make title-game-over-readback-gearlynx` はTITLE、GAME OVER voice、GAME OVER completeの全sceneでpixel mismatch=0を報告した。しかしユーザーの実機では再読み込み・リセット後もTITLE等とversion番号を含め文字化けが継続している。

現行artifact:

- `/Users/mammycloud-m4/Documents/develop-m4/atari-lynx-shooter/dist/asteroid-patrol.lnx`
- size 59903 bytes, SHA-256 `40346dd9a9280b0d55ad25ba9bea4aaa296c3cd3ee386fb69bb702865904a15a`
- `include/version.h`: `GAME_VERSION_STRING "0.53.4"`

v025はversionを更新しなかったが、v2設計 §7 はROM生成ごとの `GAME_VERSION_STRING` 更新を要求する。このためversionが旧ROMとの判別子として機能していない。

## 目的

実機とGearlynxの結果差を、旧ROM書込み/読込み、LNXカートリッジ転送方式、実機SuzyのSCB・1bpp packed bit順/アラインメント/penpal解釈、検証器の自己同型化の順で、根拠つきに切り分ける。推測でハード差異を確定しない。

## 変更してよい範囲

- 調査用スクリプト、verifier、evidence、README、`ISSUES.md`。
- 根因または旧ROM判別不能が確認できた場合のみ、最小の診断用ROMを作成してよい。その場合 `include/version.h` を `0.53.5` へ更新し、通常ROMを再生成し、絶対パス・size・SHA-256・画面上の期待versionを証跡化する。
- 診断ROMは文字描画以外、scheduler、Timer/IRQ、audio、Phase 3R、背景/可動object仕様を変更しない。

## 触ってはいけない範囲

- Phase 3R本実装、Suzy可動object移行、bounded scheduler挙動、CFG/stack、voice/cartレイアウト。
- 既存の無関係な未コミット変更の改変・revert・commit・push・stash・reset・checkout。

## 実施

1. `dist/asteroid-patrol.lnx` のLNX header、MAIN payload、現在のsource/version/生成物の対応を確認。version文字列はROM payload内に存在するか、生成日時・SHAとともに記録。
2. 実機へのROM投入方式をコードベースから推測せず、リポジトリに手順・転送ツール・既知制約があるか探索。発見できなければ「実機へ渡したファイルのSHAを確認できない」を明記。
3. cc65 Lynx TGI/Suzyの使用中SCBフォーマットを一次ソース(local cc65 source)で確認し、1bpp packed dataのbit順、row終端、literal/RLE、penpal、SCBポインタの実機差リスクを照合。Gearlynxのみで正しいと誤判定する自己同型検証（期待rendererと実装が同じ誤りを共有）の可能性を独立renderer／既知の非対称glyphで検査する。
4. `A`/`V`/`0`/`4`のような左右端・中央・非対称行を含む固定dataと動的 `static_layer_text()` の両方を静的に検査。必要ならGearlynxで実ROMのSCB payload・framebufferを取得して期待配列と一致させる。
5. 最小診断ROMを生成した場合のみ、v025のTITLE/GAME OVER readback、clean verify、静的layer readback、`git diff --check`を実行する。version `0.53.5` がTITLE期待画素・ROM payload・evidenceで一致することを必須にする。

## 完了条件

- 実機差異の原因分類を `confirmed` / `likely` / `not determinable locally` に分け、各根拠を示すこと。
- 実機に渡すべき通常ROMの絶対パス、SHA-256、size、`GAME_VERSION_STRING`を正確に提示できること。
- 必要な修正を行った場合: host test / lint相当 / clean ROM build / Gearlynx TITLE/GAME OVER framebuffer readback / static layer readbackを実行してPASS。設計差分を報告。
