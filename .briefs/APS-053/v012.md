## 実施 A: O5 zero-pen no-write差分bisect

1. cc65 driverの実`cls_sprite`の全23Bとv011 Run B SCBを証跡に並べ、異なるcontrol/type/reload/palette/data項目を明示する。推測ではなくsource位置/バイト値を残す。
2. release ROMへのデバッガ注入だけで、clearを含まない1×1 single pixelまたは2-chainを使う追試を**最大3走行**する。Run Bから一項目ずつ、最優先で`cls_sprite`と同じ「pen 0が実際に書かれる」sprite type/controlへ置換する。他はRun Bと同一（sentinel、座標、data、process分離、raw page観測）。
3. 各走行について、注入SCB bytes、clsとの差分、`VIDBAS`から算出したtarget byte、期待値/実値、全変化byte、判定をJSON/rawへ保存する。pen0が`0xAA→0x0A`となればzero-pen no-writeの原因control/typeまで分離。依然不変なら次の差分を実施し、最大3で止める。
4. 最大3で未分離なら、証拠済みの候補・未証明候補・次に必要な設計判断をBLOCKEDとして記録する。penpal修正は実装しない。
