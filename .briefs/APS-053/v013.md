## 確定根拠

- O5 Run A: 1bpp値1・`TYPE_NONCOLL`・非zero `penpal[0]`で2-chain描画成功。Run B: 同じSCBで`penpal[0]=0`は不変。C1: `sprctl0=0x05 TYPE_NONCOLL`を`0x01 TYPE_BACKNONCOLL`へ変えるだけで`0xAA→0x0A`。`TYPE_NONCOLL`はペン0を透明化する正しい仕様であり、背景assetの値0透明は維持すべき。
- 現static layerは1bpp値1を`penpal[1]=color`へ、2bpp値2を`penpal[2]=detail`へ割り当てているが、Suzyは値1=`penpal[0]`下位、値2=`penpal[1]`上位を参照する。したがって現行の非zero assetが透明ペン0になっている。直す対象は**penpal nibble割当**で、SCB typeをBACKNONCOLLへ変えることではない。
- readback verifierも`penpal[value]`という同じ誤モデルで、正しいnibble lookupへ直す必要がある。
- channel 1のsourceはSFX注入直後に`output_sfx=[1,15,28,3]`、次の同期境界直前には4-step SFX消費済み。失敗はverifierが適用後の同一同期境界へ再注入する順序問題。release音声sourceの修正は不要。

## 実装

1. `reset_scb`等の共通SCB初期化を、Suzyの正しい16-nibble palette対応へ変更する。pixel1は`penpal[0]`下位から既存`color`、pixel2は`penpal[1]`上位から既存`detail`を取得すること。pixel3を現assetで使用する場合はその値の正しいnibbleも明示的に設定する。pixel0は0かつ`TYPE_NONCOLL`透明のまま。既存各stage/HUD/文字/clearの意図するpaletteを変えない。
2. independent rendererを値`v -> penpal[v >> 1]`、偶数=上位/奇数=下位ニブルで実装し、正しいpixel expectationを生成する。stage 1/2/3で非zero期待数・raw framebuffer/readbackを検証し、旧誤モデル期待を残さない。
3. `make static-layer-readback-gearlynx`がstage 1/2/3のSCB構造、raw physical page、pixel照合をPASSするまで修正する。O5診断は回帰としてRun A/C1成功、Run B透明不変の期待でPASSとする。
4. channel 1 verifierはSFXを**次の実sound applyより前**に注入し、そのapply直後にMIKEYを観測する順序へ修正する。短いSFXのため同期後再注入・次同期前観測の競合をなくす。source/BGM/SFXデータ/閾値は変更しない。channel 0/1/2すべて同じ品質条件でPASSさせ、JSONに注入→apply→MIKEYの因果を保存する。
