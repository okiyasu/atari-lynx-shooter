## 現状・設計判断

- APS-045 baseline: version `0.45.0`、LNX 60,217 bytes、sprite RODATA 1,245 bytes、BSS `0x4ED`=1261 bytes、MAIN final `0xB82D`、C stack start `0xB838`、残余11 bytes。通常enemy capacityは現行`GAME_MAX_ENEMIES=4`だが、APS-046は8体をtrue capacity/測定基準にする。
- 75Hz timing sourceはLynx TGIの` tgi_setframerate(75u)`/`tgi_busy()`のみを使う。CPU命令数やhost wall clockに依存する較正busy-loopは禁止。draw完了後、次のhardware frame boundaryまでの`while (tgi_busy()!=0u) {}`をframe終端へ明示配置し、8体未満で余る処理・描画時間を同一75Hz frame内の安全なhardware waitとして吸収する。8体時にframe budgetを超えた場合はwaitを短縮/省略するだけで、logic update数を増減・skip・sleepしない。75Hzの1 frame=13,333.333...us、測定閾値は75Hz同期の連続frame間隔が12,000〜15,000us（計測器/OS jitterを許容）と明記し、hardware completionを正しさの基準、wall-clockはadvisory値とする。
- 表示/活動countはNORMALで`active && rect.x < GAME_SCREEN_WIDTH`の通常敵、BOSSでactive boss 1体を含む。画面外のpre-spawn slot、enemy bullet、player、environmentはcountに入れない。NORMAL/BOSSで同時combatantは必ず`<=8`。
- 既存ステージの難度意図を保つため、stageの初期/respawn活動数は現在の4を維持してよい。ただしruntime capacity、stage dataの明示上限、host/Gearlynx injectionは8を扱い、9を必ず拒否する。8枠化に伴い4枠分をinactiveにする場合、spawn/movement/fire/drop/scoreの既存4枠挙動はbit-for-bit相当で維持する。
